Brim

Run several Claude Code accounts on one Mac, and keep it fast.

See every account's usage, start on the one with room, move a conversation when one hits its limit, and clear the leftover dev processes that eat your memory. Plus a system monitor and the Mac tools you reach for every day.

View on GitHub Build from source

Brim is a free, open-source macOS menu bar app for Apple Silicon Macs. It lets one person use several Claude Code accounts on the same Mac, ends leftover development processes when memory gets tight, and bundles a system monitor, Port Manager, Kill Process, Cleaner, Uninstaller, Homebrew manager, app updates, clipboard history, keep awake and a Dynamic Island. No account, no telemetry, no subscription. Written in Swift and licensed GPL-3.0-or-later.

Claude Code accounts, side by side

Each Claude Code account gets its own config folder, signed in once by Claude Code itself. Brim shows their usage and starts you on the right one.

  • Usage at a glanceEach account's weekly limit, model-specific limits and renewal times, in the menu bar panel and a Claude Code status line.
  • Automatic pickingclaude starts on the account whose weekly limit renews soonest; cc <account> starts on a named one.
  • Move when you hit a limit/exit, then cx continues the same conversation on another account. Every account sees every conversation in /resume.
  • MCP servers per repoEvery MCP server is on everywhere by default; switch one off for a single repo, or add servers only one repo uses.
  • Hands off your credentialsBrim never reads, copies or refreshes a Claude sign-in. Each account signs in through a private browser window, so the wrong account can't approve it.
# start on the account that renews soonest
$ claude

# start on a specific account
$ cc work

# hit the limit? /exit, then continue the same
# conversation on another account
$ cx
$ cx --to personal

Memory that stays free on a dev Mac

Long agent sessions leave dev servers, test runners and watchers behind. Brim finds what is actually holding memory and deals with it only when it matters.

Inform

Memory pressure, swap and compressed memory, plus leftover dev process groups and apps unused for hours, with their memory.

Notify

One notification per memory-tight episode, naming what holds the memory, with Quit and Review.

Automatic

Only while memory is tight, and only orphaned dev process groups, checked again right before each one ends.

Runaway brake

Ends a process whose memory footprint explodes, such as a test runner growing by hundreds of gigabytes, and logs it.

fseventsd leak

Spots the known macOS fseventsd memory leak and tells you how to clear it.

Never in the way

Names, paths and apps you protect are never touched, and nothing is ended automatically while memory is fine.

Monitor and Mac tools

Everything from the menu bar. Each feature can be turned off, and a feature that is off stops loading and asks for no permissions.

System monitor

CPU, GPU, memory, network, disk and power, with alerts that ignore short spikes. Connected devices and fan control.

Port Manager

Every listening port and the process behind it, ended in one click.

Kill Process

Find and end processes, including ones that won't quit.

Cleaner

Caches, logs, developer files, old device backups, app leftovers and forgotten screenshots, moved to the Trash.

Uninstaller

Removes an app together with the files it leaves around the system.

Homebrew & App Updates

Manage formulae and casks, and find new versions of your apps.

Clipboard history

Search, pins, ⌘1 to ⌘9 pasting and paste as plain text. Concealed content is never recorded.

Keep awake

Keep the Mac awake, including with the lid closed.

Dynamic Island

An island around the notch with controls, clipboard, system and AI agent usage.

Private by design

Everything Brim reads stays on your Mac. It has no account, no analytics, no crash reporting and no server of its own, and it uses the network only for a feature you turned on. Read the privacy notes.

Build from source

Brim needs macOS 14 or newer on an Apple Silicon Mac, and the Xcode Command Line Tools. It builds with plain swiftc: no Xcode project, no dependencies.

$ git clone https://github.com/eliseorobles/brim.git
$ cd brim
$ BRIM_SIGN_IDENTITY=- ./build.sh --dev --install

BRIM_SIGN_IDENTITY=- signs your build ad hoc; name your own Apple certificate there to keep macOS permissions across rebuilds. Fan control needs the maintainer's signed build; everything else works in yours. See CONTRIBUTING.md.

FAQ

What is Brim?

Brim is a free, open-source macOS menu bar app for Apple Silicon Macs. It combines a Claude Code multi-account manager, a memory manager for development machines, a system monitor and Mac utilities such as a Port Manager, Cleaner and Uninstaller.

How do I use more than one Claude Code account on the same Mac?

Give each account its own Claude Code config folder with CLAUDE_CONFIG_DIR (for example ~/.claude-work) and sign in to each one once. Brim sets this up for you, shows every account's usage, and adds the claude, cc and cx shell commands to start on, or move between, accounts without signing out.

Does Brim read or store my Claude credentials?

No. Each account's sign-in stays with Claude Code in that account's own folder and Keychain item. Brim never reads, copies or refreshes a token.

How do I continue a Claude Code conversation on another account when I hit a usage limit?

Type /exit, then run cx. Brim continues your latest conversation in that folder on another account with room, or on the one you name with cx --to <account>.

How do I see Claude Code usage limits for each account?

Brim's menu bar panel and its Claude Code status line show each account's weekly limit, model-specific limits and when they renew.

How do I free memory used by leftover dev servers and test runners on a Mac?

Brim's Memory module lists orphaned dev process groups (ones whose editor or terminal is gone) with their memory, and ends them with one click, or automatically while memory is tight.

How do I find which process is using a port on macOS?

Open Brim's Port Manager to see every listening port and the process behind it, and end it from there. Without Brim, run lsof -nP -iTCP:3000 -sTCP:LISTEN.

Is Brim free? Does it collect data?

Brim is free and open source under GPL-3.0-or-later. It has no telemetry, no analytics and no account.

Does Brim run on Intel Macs?

No. Brim needs an Apple Silicon Mac and macOS 14 or newer.

How is Brim related to Vorssaint?

Brim is a hard fork of Vorssaint, an open-source macOS menu bar toolkit. It keeps Vorssaint's monitor and Mac tools, removes the window, dock, mouse, keyboard and sound features, and adds the Claude Code accounts and Memory modules, under its own name, icon, bundle ID and signing identity.

Is Brim made by Anthropic?

No. Brim is an independent project and is not affiliated with or endorsed by Anthropic. Claude and Claude Code are trademarks of Anthropic.
